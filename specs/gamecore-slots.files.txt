CONVENTIONS THAT APPLY TO EVERY SLOT IN THIS FILE
  * Every slot here is plain __cdecl: the gamecore function ends in a bare `ret`, and every
    FFXiMain site cleans up with `add esp,4*argc`. Pop count = 0 for all of them. None uses ecx
    (no thiscall). Return value in eax (edx also for none of these).
  * "Root" = gamecore global 0x103dfa24 (char[0x200]): the viewer's install directory,
    stored WITH a trailing backslash, '/' converted to '\'. It is set by slot 125 (+0x1f4,
    0x10048a40) / slot 1456 (+0x16c0, wide variant); the retail launcher/app.dll set it, FFXI
    never does. On this machine: the retail install's viewer folder (62 chars;
    consistent with the live log: id 0x13 -> 0x47 = 62 + len("data\dic\")).
  * "User index" = gamecore global 0x100992e0 (int; slot 870 +0xd98 sets it; read via
    0x10045fd0 under mutex 0). Negative is treated as 0. It becomes the two digits of "homeNN"
    (tens = (u/10)%10, units = u%10). Normally 0 (the Viewer's first member slot).
  * "Language code" = slot 421 (+0x694, 0x10018200) = global 0x100740f8 (fallback 0x100aa31c).
    Live value: 1. 0 = Japanese, 1 = US English, 2..8 = EU EN/FR/DE/IT/ES/EL/PT.
    (0x10018200 is also what FFXi.dll stores at param block +0x28.)

Signature  : int PatchVerDecrypt(const u8 src[0x120], char *out, int outsize, int product);
             product = title id as a number: 1 FFXI, 2 Tetra Master, 1000 the viewer.
Returns    : 0 on success, -1 on failure (bad key/checksum, or outsize <= strlen(version)).

State/OS   : Registry: RegOpenKeyExA(HKLM, <launcher Interface key, US variant>, 0, KEY_QUERY_VALUE)
             when gamecore global 0x100aa318 != 0 (US build), else the non-US variant of that key;
             a non-empty string at 0x103dfc24 overrides the key path. (Key strings are stored
             Caesar +1 and decoded by 0x10049da0: each alphabetic char minus 1.)

Algorithm (all verified: a Python reimplementation decrypts all three retail patch.ver files to
  exactly what the emulated gamecore produces: FFXI "30260805_0", Viewer "20110829_E",
  TetraMaster "20040909_0"):
  1. seed64: r = registry string. k[8] = 0; for i < strlen(r): k[i&7] += r[i] (bytes, mod 256);
     seed64 = little-endian u64 of k.  Tries, in order: (a) over strlen(r), (b) over all 0x80
     bytes of the value buffer (differs only if junk follows the NUL), (c) seed64 = 0 (also the
     only try when the registry read fails). First try whose decrypt succeeds wins.
  2. key64 = seed64 + (int64)(int32)product.
  3. Key schedule (0x10007bc0): lo = key64 & 0xffffffff, hi = key64 >> 32;
       s[0..3] = LE(ror32(hi,16)), s[4..7] = LE(rol32(lo,8));
       s[0] += 0x45; for i=1..7: b = s[i] + s[i-1] - 0x2c; s[i] = (s[i-1]<<2) ^ b ^ 0x45 (bytes);
       K[0] = LE u64 of s; K[j] = K[j-1]*5 mod 2^64 for j=1..31.
  4. Decrypt 8-byte blocks (size must be a nonzero multiple of 8; 0x120 = 36 blocks);
     ctr = 0 (bytes processed), sum = 0 (u32). For each block at offset off:
       idx = (ctr>>3) & 31; S = (sum of the 8 bytes of K[idx]) mod 256
       byte stage: d = ((ctr>>3) ^ 0x45) & 0xff;
                   for k in 0..7: c = in[off+k]; x[k] = ((c ^ d) + 0xc0 - S) & 0xff; d = c;
                   (this is 8 rounds of x = SBOX[x] - Kbyte[j] with SBOX = gamecore 0x100715e4,
                    which is exactly x+0x78; 8*0x78 = 0x3c0 = 0xc0 mod 256)
       word stage: v = LE u64 of x; v -= K[idx];
                   t = ctr; t = (t<<10)|ctr three times (64-bit); t += 0xa1652347;
                   v ^= t; v ^= K[idx]; swap the 32-bit halves; store LE at out[off].
       sum += out[off] + out[off+4];  ctr += 8.
     Before the LAST block, remember sum_before_last. Success iff
       sum_before_last == u32 LE out[0x11c]; the function then returns u32 LE out[0x118]
       (0x118 = 280 in all three files; treated as ok if >= 0).
  5. Plaintext layout (0x120): 0x00..0x17 zero; 0x18 version string NUL-padded; zeros;
     0x118 u32 = 0x118; 0x11c u32 = checksum. The slot copies the string at 0x18 (fails with
     -1 if outsize < strlen+1).
KEY RECOVERY WITHOUT THE REGISTRY (important for macOS): blocks 0 and 1 are known plaintext
  (all zero), so K[0] is recoverable: for each (S0,S1) in 256x256 compute the byte stage, then
  solve (v0-K)^K = t0 and (v1-5K)^(5K) = t1 bit by bit from the LSB (low bits of K fix the low
  bits of both equations), then keep the K whose byte sums match S0/S1 and whose full decrypt
  passes the checksum. Python does all three retail files in < 0.4 s; C is instant. Result
  K[0]: FFXI 0x7796ab35ec794845, Viewer 0xee8e6f4611e93b7e, TM 0x1a45575caace2f7b.
