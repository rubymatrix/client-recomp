Carrying addresses over
-----------------------
Old -> new addresses by byte matching: a window around the old address, every relocated dword
(from the private .text relocation table) wildcarded, must match exactly once in the new .text;
windows widen until one does. Data addresses: map the .text sites that reference them and read
the new operand. Results used:
  manual verdicts (r1builds.py) all 7 NOT_CODE, 3 REDECODE, 5 switch overrides mapped
                                (0x1015bef0/0x1015beed by hand: same -0x10 shift, verified by
                                disassembly; the byte window failed because of the 0xccc change)
  character table pointer       0x104df7b0 -> 0x104df770 (layout unchanged: +0x13820, stride 0x8c)
  Present call site             0x100035cb (unchanged)
  difftest CRT slice            each -0x40 (strlen 0x10317440 ... strpbrk 0x10322bb0), all entries
These are in FFXIRecompile meta/builds.json.

Method
------
Ghidra 11.3.2 headless, scratch project, as for 2026-08-22: import + auto-analysis, then
Discover -> Discover2 (each to a fixpoint) -> Switches -> SwitchAudit -> Conflicts ->
BogusCheck APPLY -> the same again -> Classify / Diagnose / RecompStats -> Export.
The manual verdicts now live in r1builds.py, per module and build (by PE timestamp).

promoting. The translator is indifferent: x86c.py follows jumps to non-entry code and inlines it
