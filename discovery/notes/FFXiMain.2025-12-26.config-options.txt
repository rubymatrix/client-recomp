What it is
----------
Everything the in-game Config menu sets is one table of numbered options, the PS2 client's
FsConfig: an object whose +4 is an array of entries of 0x2c bytes, indexed by the option's number.

  entry +0x04  the option's number (FS_CONFIG)
        +0x08  its value
        +0x0c  its type: 4 = saved per character in USER\<id>\cnf.dat; 1 and 2 go with
               PlayOnline's settings (the save loop flags the object dirty for them)
        +0x20  a second value, which the loader copies into +0x08 for some options when it
               reads an older-format cnf.dat

  0x1062da2c   the pointer to the config object (the first of a run of such singletons:
               0x1062da78, builds.json's modern.config_inst, is the next one)
  0x10192310   getConfig(option) -> value, or -1 without the object:
                 8B 0D ?? ?? ?? ??  85 C9  74 0B  8B 44 24 04  50  E8 ?? ?? ?? ??  C3  83 C8 FF  C3
               (a second function of the same bytes follows it, reading the same global)
  0x101922f0   changeConfig(option, value), cdecl, 1 if it changed: checks the value against the
               option's range and runs the option's callbacks, as the Config menu does:
                 8B 0D ?? ?? ?? ??  85 C9  74 10  8B 44 24 08  8B 54 24 04  50 52  E8 ?? ?? ?? ??  C3  83 C8 FF  C3
  0x10193da0   findConfigSubject + read; 0x10193d30 the thiscall behind changeConfig (option 0xce is
               always applied, even unchanged); 0x10194870 _setConfig
  0x10194320   saves cnf.dat; 0x101943c0 loads it (0x10193dc0 load-and-apply, 0x10193e60 save)

The table walk is 0x2394 bytes: 207 options (0x2394 / 0x2c).

USER\<id>\cnf.dat
-----------------
A dword 5, then the value of every type-4 option in option order: 185 of them in this build (744
bytes). The loader also takes a first dword of 0x05000000 (an older layout) and older, shorter
files. The game writes it when a character logs out (setting option 0xa2 to 0, then 2, first).

The game's own shadows
----------------------
Option 58 (0x3a) is Config > Shadows: 0 Normal, 1 Off, 2 High. It is type 4, saved value 46
counting from 0: cnf.dat offset +0xBC. Seen by logging the table while the setting was stepped
through its three choices in game, and matching the values three characters' cnf.dat files held.

The renderer's sun shadows make the game's own redundant (and they cost more): VanaCore calls
changeConfig(58, 1) once a character's config has loaded (the load changes ~20 options in one
frame), keeps the value the player had, and puts it back when its own shadows are off. The same
call would suit host64 while its sun shadows are on.
